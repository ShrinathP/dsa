
Before trying to memorize the entire solution, first make sure you're comfortable with these three ideas independently:

1. Queue stores paths instead of words.
2. Copy the path before pushing it into the queue (new ArrayList<>(vec)).
3. Delay removing visited words until the entire BFS level is processed (usedOnLevel).

=> Step 1 -> In Word Ladder I - we forget the first word, we store second transformation and steps needed
---------

(hit, 1)

(hit,1)

And Generate:

Very simple.

=> Step 2: -> Now We want the entire path, not just the shortest distance.
---------
Instead of storing

we store
[hit, hot]

Instead of
'dog'
we store
[hit, hot, dot, dog]

So now the queue becomes
Queue<ArrayList<String>>

=> Step 6: Why usedOnLevel?
---------
In Word Ladder I we removed words immediately.

Example
hit
 ↓
hot
Remove
hot
immediately.
No problem.

In Word Ladder II this becomes wrong.
Suppose
       hit
      /   \
    hot   hut
      \   /
      dot

Both
hit → hot → dot
and
hit → hut → dot
are shortest.
If you remove
dot
after the first path,
the second path can never reach it.
So you lose answers.
Therefore we delay removal.

Current BFS level
[hit, hot]
discovers
dot
Store
usedOnLevel
dot

Don't remove yet.
Maybe another path of the same length also reaches
dot

After the whole level finishes
remove everything.

That's exactly what
if (vec.size() > level) {
    level++;

    for (String it : usedOnLevel) {
        st.remove(it);
    }

    usedOnLevel.clear();

}
does.
